## Context

`CsvImportWidget` 已经支持手动选择 Blender 可执行文件，并通过 `_save_blender_path()` 将结果写入 `config.json`。BVH→FBX 分组中的 Blender 路径输入框为只读，因此新增能力只需要补充一个按钮和一个自动查找槽函数，不需要改变已有配置结构。

用户明确要求的查找根目录是“当前运行目录下的 `libs` 文件夹”，而不是脚本所在目录。因此实现需要从 `Path.cwd() / "libs"` 出发，避免在打包运行或不同工作目录下偏离实际使用场景。

## Goals / Non-Goals

**Goals:**
- 在 BVH→FBX 分组中为 Blender 路径增加一个自动检测按钮，位置在“选择Blender路径”按钮下方
- 点击按钮后，从当前运行目录下的 `libs/` 目录枚举一级子目录，筛选目录名包含 `blender` 的候选目录
- 对每个候选目录检查其根下是否存在 `blender.exe`
- 找到第一个有效 `blender.exe` 后，更新 `bvh2fbx_blender_edit`、保存到 `config.json`、刷新转换按钮状态
- 如果未找到、`libs/` 不存在或出现异常，向用户显示明确的提示信息，不清空已有路径

**Non-Goals:**
- 不递归扫描整个磁盘或用户系统安装目录
- 不查找非 Windows 可执行名（如 Linux/macOS 上的 `blender`）
- 不引入新的配置文件或新的配置字段

## Decisions

**1. 搜索根目录固定为 `Path.cwd() / "libs"`**
- 这是用户明确指定的规则，和脚本目录、仓库目录解耦
- 替代方案：使用工程根目录或 `__file__` 相对路径；这会偏离“当前运行目录”的要求，不选

**2. 只扫描 `libs/` 的一级子目录，目录名按不区分大小写包含 `blender` 判断**
- 用户规则是“文件夹的名字只要包含 blender 字符串就算”
- 实现上使用 `child.is_dir()` 且 `"blender" in child.name.lower()`
- 一级扫描足够直接，也避免误命中过深目录

**3. `blender.exe` 仅检查候选目录根路径，不做递归深搜**
- 用户描述是“进入这个文件夹，查找 `blender.exe` 文件是否存在”
- 这样规则简单、可预测，且能避免在大型 Blender 发行目录中做慢速深搜

**4. 找到第一个有效结果就停止**
- 自动检测的目标是快速填充默认路径，不是提供多结果选择器
- 若后续出现多个候选目录，首个结果的确定性依赖目录枚举顺序；实现时建议按名称排序后扫描，保证结果稳定

**5. 失败时不覆盖现有路径**
- 自动检查属于辅助功能，不应破坏用户此前手动配置的可用路径
- 失败路径只弹窗提示，并保留当前编辑框内容

## Risks / Trade-offs

- [同级存在多个 Blender 目录] → 使用排序后的一级目录列表，始终选择第一个包含有效 `blender.exe` 的目录，行为稳定但不提供人工选择
- [当前工作目录不是仓库根] → 这是有意遵循用户要求；如果 `libs/` 不存在，应明确提示用户当前搜索根目录
- [仅检查目录根下的 `blender.exe`] → 某些 Blender 安装布局可能把可执行文件放在更深层目录；本次按用户指定规则处理，不做额外递归兼容
